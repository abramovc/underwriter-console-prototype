How Intuition works.

Intuition takes workflow tags and provider-native signals, normalizes them into canonical concepts, groups them into cleaner underwriting insights, and turns those into recommended actions for review. The goal is to make manual review easier to understand without overcomplicating the editing process for a small team.

View Intuition

Current system

Today, Intuition starts with raw tags and provider signals, maps them into shared concepts, rolls those up into insight buckets, and then picks the best next actions for the underwriter or applicant.

Step 1
Raw signals

Workflow tags, reason codes, and provider-specific inputs come in.

Step 2
Canonical concepts

Those signals get normalized into shared meanings the team can reason about.

Step 3
Canonical insights

Related concepts are grouped into cleaner underwriting themes.

Step 4
Actions

The system recommends the next best follow-up steps based on the dominant concern.

Canonical insights

The concept layer above gets rolled into a smaller set of underwriting themes that are easier to read in the UI.

Insight Purpose
Identity Integrity Is the identity real, consistent, and attributable to one person?
Contactability Can we reliably reach and verify the applicant?
Fraud / Velocity Are there synthetic, abuse, or repeated-attempt patterns?
Compliance Screening Are there sanctions, watchlist, PEP, or adverse media concerns?
Business Legitimacy Does the business appear real, registered, and consistent?
Bank Ownership Does the payout account belong to the applicant or business?
Positive Verification What evidence increases confidence in the application?
Other Signals Anything that does not yet fit a cleaner bucket.

Intuition logic

The page itself is lightweight, but the logic underneath still follows a clear chain: normalize signals, group them, summarize them, then select actions.

Normalize

normalizePayload.js builds the normalized review object from raw input and mappings.

Group + summarize

conceptGroups.js, narratives.js, insightBuckets.js, and insightSummaries.js shape the underwriting story.

Action selection

conceptActions.js and recommendedActions.js translate the dominant concern into next steps.

Concept-to-action logic and page logic are tightly related, so keeping them together here makes the system easier to understand.

Making updates

This does not need to be overly formal. For this team, the cleanest update path is simple.

  1. Leave a comment or note in the Google Sheet.
  2. Review the change and decide what should actually ship.
  3. Update the relevant CSV or JS file in the repo.
  4. Test in Intuition with a few representative payloads.
  5. Commit, deploy, and verify the output.

Quick guide

  • If you want to change a concept, start with concept_dictionary.csv.
  • If you want to change a mapping, update the matching provider CSV.
  • If you want to change an insight bucket, update insightBuckets.js.
  • If you want to change an action, update recommendedActions.js and sometimes conceptActions.js.
  • If you want to change hero behavior, review insightSummaries.js.

For non-engineering edits, team members can route changes through you and you can decide what is worth syncing into the repo.
